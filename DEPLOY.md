# Deploy

Live site: https://kiosk.creka.online

## How it ships (`bash deploy.sh`)
- Builds locally (`npm run build`, Astro + `@astrojs/node` standalone), tars `dist/` + `Dockerfile` + `package*.json` (excluding `dist/client/captures`) over SSH.
- Server: `mindaadmin@208.87.132.15`, build context `~/creka/kiosk/app`.
- Server runs `docker build -t creka-kiosk`, removes the old container, and runs a new `creka-kiosk` (`--restart unless-stopped`, network `npm_web`, no published port; nginx proxy manager forwards to `creka-kiosk:80`).
- Container runs `node dist/server/entry.mjs` on port 80 (`HOST=0.0.0.0 PORT=80`).
- Captured photos: `/api/save-capture` writes with `fs` to `CAPTURES_DIR` (`/app/dist/client/captures/demo/camwithnkob`), mounted from `~/creka/kiosk/captures` on the host, so they survive redeploys. The node server serves them at `/captures/...`.
- Kiosk registry, capture links and kiosk errors live in **creka_backend** (`/api/v1/photobooth`, CrekaCampaignRepo tables `photobooth_kiosks/_captures/_errors`), not on this server. `BACKEND_URL` (default `https://creka.online`) points at it; `/admin/dashboard` edits go through `/api/kiosks`. `/admin/dashboard` is behind the Creka admin OTP login (`/api/creka/auth/otp/*`, via `/api/auth`): the Bearer token sits in an httpOnly `creka_admin` cookie (7 days) and the backend requires an admin/superadmin role on every dashboard route (`/api/v1/photobooth`). Kiosk-side calls (`/k/<id>`, captures, errors, touch) need no login. Deploy + migrate the backend (`mix ecto.migrate -r CrekaBackend.CrekaCampaignRepo`) before this app. **creka_backend ships via** (done for real 2026-11-05, release 0.7.2): branch off `origin/main`, push, `gh pr create --base main`, wait for the PR checks (`Format, deps, tests`; the 54 known failures are non-blocking), `gh pr merge <n> --merge`; then `gh workflow run ci.yml --ref main -f bump=patch` (bumps `mix.exs`, tags `v<ver>`, pushes `sooonism/creka_backend:<ver>` to Docker Hub); then `ssh minda-vps 'cd /home/mindaadmin/creka_backend && ENV_FILE=/home/mindaadmin/creka_backend/backend.env NPM_NETWORK=npm_web TAG=<ver> ./deploy.sh'` (pulls, backs up uploads, replaces the container, migrations run on boot). Merge into `main` for a production build, into `dev` for a testing build (a push to `dev` publishes `:dev` by itself, for the `creka_backend_test` container). Branch from `origin/main`, not `dev-soon`: it carries an older copy of the photobooth code.
- Captures are dual-written: the local copy (served at `/captures/...`, used by the photo page/QR) and a copy POSTed to the backend (`uploads/photobooth/<kiosk>/<date>/<uuid>.png`, `creka_uploads` volume, served at `https://creka.online/uploads/...`).
- Per-kiosk captures live in `CAPTURES_DIR/<kiosk-id>/`. Each Pi's Chromium opens `https://kiosk.creka.online/k/<kiosk-id>` (redirects to the module chosen in the dashboard).
- Dashboard → kiosk commands (Ping, Check camera): the kiosk page (any page opened with `?kiosk=<id>`) holds a long-poll on `/api/kiosk-cmd`; `/api/kiosk-do` (admin only) hands it a command and waits up to 30 s for the reply. In memory in this node process, so no extra env or install; a server restart just drops pending commands. Ping proves the Chromium page on the Pi is alive; Check camera returns a 480 px JPEG of the page's canvas plus a brightness number. Check: `node --experimental-strip-types scripts/kioskCmd.check.ts`.
- Visitor events: the photo page (`/photo?id=..&kiosk=<id>`, also `/sponsor`, `/donate`) POSTs `open` on load and `whatsapp` / `instagram` when the share button is tapped to `/api/event`, which relays to creka_backend `POST /kiosks/<id>/events` (table `photobooth_events`: kiosk, type, photo id, the kiosk's location at that time). Taps, not proof of a send. Also `save` (Save photo button) and `profile` (Kiosk by Creka link, to Instagram), `creka` (Powered by Creka link, to creka.online) and `sponsor` (tap on the sponsor banner, only the /sponsor page has one). Each event carries `source`: the kiosk QR adds `&s=qr`, and the link in the WhatsApp share text is rewritten to `&s=wa`, so opens split into QR vs shared-link (dashboard shows both). One `open` per photo per device (localStorage). Backend (event `source` column, `save`/`profile` types) must be deployed first, otherwise those events are dropped. Needs `?kiosk=` in the URL, so the QR links carry it; without it nothing is recorded. Dashboard card shows the totals. Backend must be deployed + migrated (`mix ecto.migrate -r CrekaBackend.CrekaCampaignRepo`) for it to record; until then the relay silently drops events.
- Kiosk mode: each kiosk has `mode` (`actual` default, or `debug`) in creka_backend (`photobooth_kiosks.mode`), set on its dashboard card. `/k/<id>` redirects to `<module>?kiosk=<id>&mode=actual`, or without `mode=` for debug (debug panel). The card's **Reload page** goes through `/k/<id>`, so a changed module or mode applies without SSH. Backend must be deployed + migrated first (until then `/k` treats every kiosk as `actual`).
- Dashboard health: kiosk pages POST `/api/heartbeat` every 20s (in memory, no mount needed); `/api/storage` sums `CAPTURES_DIR` and the dashboard warns at `CAPTURES_LIMIT_MB` (code default 1024; `deploy.sh` passes 5120 = 5 GB from 2026-11-05, override with `CAPTURES_LIMIT_MB=... bash deploy.sh`). Warning only, nothing is blocked. A photo is ~0.4 MB, and every capture is stored twice on the VPS (this app's volume and creka_backend uploads), ~40 MB each for 71 photos.
- Config from gitignored `.env` (see `.env.example`); script defaults match it. No secrets in the repo.

  - Kiosk page watchdog (2026-11-04, `scripts/kiosk-watchdog.sh`, user service `kiosk-watchdog`, installed together with kiosk-health): every 15 s it checks Chromium via `localhost:9222`; if the page is Chromium's "can't be reached" page (page title == URL host) and the site answers, it `pkill`s Chromium and the autostart loop relaunches the kiosk. ## Kiosk health monitoring (Pi → creka_backend)
- `scripts/kiosk-health.sh` runs every minute from a systemd **user** timer (no root; autologin session + linger) and POSTs `https://creka.online/api/v1/photobooth/kiosks/<id>/health`: uptime, CPU temp, disk/RAM free %, wifi %, screen/camera/Chromium/clock-sync, current Chromium URL. Cost: ~0.5 s wall per run, ~0 CPU.
- Install on a Pi (as the kiosk user): `scp scripts/kiosk-health.sh scripts/install-kiosk-health.sh orangepi@<ip>:/tmp/ && ssh orangepi@<ip> 'bash /tmp/install-kiosk-health.sh <kiosk-id>'`. Writes `~/.config/kiosk-health.env`, `~/.local/bin/kiosk-health`, `~/.config/systemd/user/kiosk-health.{service,timer}`. Check: `systemctl --user list-timers` / `journalctl --user -u kiosk-health`.
- Installed on `orangepi-1` = the Zero 3W (2026-11-04, via Tailscale: `scp` both scripts to `/tmp`, then `bash /tmp/install-kiosk-health.sh orangepi-1`; no sudo). The script reads the page URL from Chromium's `localhost:9222`, so the kiosk autostart **must** launch Chromium with `--remote-debugging-port=9222` (added to the Zero 3W autostart the same day); without it `url` is empty. The backend's "wrong page" alert needs the kiosk id in the URL: the Zero 3W now opens `https://kiosk.creka.online/demo/camwithnkob/?kiosk=orangepi-1&mode=actual` (set 2026-11-04, backup `autostart.bak-pre-url-20261104`); switch to `/k/orangepi-1` once `/k/[id]` is deployed.
- Installed on `orangepi-4pro` (2026-10-31). Until the new creka_backend is deployed the endpoint 404s and the journal shows `status=22`; that is expected.
- Backend side (`creka_backend`): `KioskMonitor` alerts by email (`KIOSK_ALERT_EMAIL`, active 08:00–21:59 MYT) on Pi silent >5 min, CPU ≥80 °C, disk <10% free, RAM <5%, camera/screen/Chromium missing, wrong page (URL lacks the kiosk id), clock unsynced. Daily rows live in `photobooth_health` (run `mix ecto.migrate -r CrekaBackend.CrekaCampaignRepo`). Add each kiosk id to the server's `KIOSK_IDS` env so the 10:00 wake-up check expects it.

## SOP: set up a new kiosk Pi
Worked out on the Zero 3W (`orangepi-1`, 2026-11-04). `<ip>` = LAN IP, `<id>` = kiosk id (e.g. `orangepi-2`). Read-only/non-root steps can be run by Claude over SSH; steps marked **[sudo]** need the Pi's sudo password, so give the user a `! ssh -t orangepi@<ip> 'sudo ...'` line to run (Claude can't type it). Tick each in order; every step has a check.

0. **Prereqs**: OS flashed, user `orangepi`, on a wifi you control, `ssh-copy-id orangepi@<ip>` from the dev Mac (default pass `orangepi`), camera + display attached. Add the kiosk in `/admin/dashboard` and its id to the server's `KIOSK_IDS` (and migrate/deploy creka_backend first, see above).
1. **Survey (read-only)**: `ssh orangepi@<ip> 'uname -r; nmcli con show; cat ~/.config/openbox/autostart; ls /dev/video* /dev/net/tun; findmnt /; timedatectl'`. Note what's missing (`/dev/net/tun` decides step 2).
2. **Tailscale [sudo]**: `ssh -t orangepi@<ip> 'curl -fsSL https://tailscale.com/install.sh | sh && sudo tailscale up --ssh'`, open the printed login link. If `/dev/net/tun` is missing (kernel without TUN, as on the Zero 3W): `sudo sed -i 's|^FLAGS=.*|FLAGS="--tun=userspace-networking"|' /etc/default/tailscaled && sudo systemctl reset-failed tailscaled && sudo systemctl restart tailscaled && sudo tailscale up --ssh`. Check: `tailscale status`; then use the tailnet IP (first connect: `-o StrictHostKeyChecking=accept-new`).
3. **Wifi profiles [sudo]**: office wifi priority 10, phone hotspot priority 5. Per network, the user runs (typing SSID and password at the prompts, never in chat/repo): `ssh -t orangepi@<ip> 'read -p "SSID: " S; read -sp "Password: " P; echo; sudo nmcli con add type wifi ifname wlan0 con-name "$S" ssid "$S" wifi-sec.key-mgmt wpa-psk wifi-sec.psk "$P" connection.autoconnect yes connection.autoconnect-priority <10 or 5>'`. Phone hotspot must broadcast 2.4 GHz. Check: `nmcli -f NAME,AUTOCONNECT,AUTOCONNECT-PRIORITY con show`.
4. **Chromium autostart**: `scp scripts/openbox-autostart.sample orangepi@<ip>:/tmp/a && ssh orangepi@<ip> 'cp -n ~/.config/openbox/autostart ~/.config/openbox/autostart.bak; sed "s/<kiosk-id>/<id>/" /tmp/a > ~/.config/openbox/autostart.new && mv ~/.config/openbox/autostart.new ~/.config/openbox/autostart'` (use `mv`, never edit the running script in place). Gives: network-wait loop, crash-bubble flags, `--remote-debugging-port=9222`, URL with `?kiosk=<id>&mode=actual`. Apply without reboot: see "Apply an autostart edit". Check: kiosk shows on the screen; `curl -s localhost:9222/json | jq -r '.[0].url'` contains `<id>`.
5. **Hardening [sudo]**: `scp scripts/harden-pi.sh orangepi@<ip>:/tmp/ && ssh -t orangepi@<ip> 'sudo bash /tmp/harden-pi.sh'` (apt auto-update off, journald volatile, ext4 `commit=30`).
6. **Timezone [sudo]**: `ssh -t orangepi@<ip> 'sudo timedatectl set-timezone Asia/Kuala_Lumpur'`, then restart Chromium.
7. **kiosk-health + kiosk-watchdog** (no sudo): `scp scripts/kiosk-health.sh scripts/install-kiosk-health.sh orangepi@<ip>:/tmp/ && ssh orangepi@<ip> 'bash /tmp/install-kiosk-health.sh <id>'`. Check: `~/.local/bin/kiosk-health; echo $?` is 0 (the backend returned 2xx).
8. **Wifi fallback hotspot [sudo]**: `scp scripts/wifi-fallback.sh scripts/wifi-setup.py scripts/install-wifi-fallback.sh orangepi@<ip>:/tmp/ && ssh -t orangepi@<ip> 'sudo bash /tmp/install-wifi-fallback.sh <id>'` (pick a hotspot password, store it in the password manager). Check: `systemctl is-active wifi-fallback`.
9. **Acceptance tests** (do all before shipping): (a) cold reboot with the office wifi off and the phone hotspot on: Pi rejoins, Tailscale reachable, kiosk page up; (b) `sudo /opt/wifi-fallback/wifi-fallback.sh now` beside the Pi: join `creka-setup-<id>`, submit a network, Pi rejoins; (c) with no known network in range for 2+ min the setup hotspot opens by itself (still unverified as of 2026-11-04), and with wifi up but no internet (`sudo ip route del default`) it opens after ~3 min; (d) pull the power, boot: no "Restore pages?" bubble, kiosk comes up; (e) camera detected (`ls /dev/video0`) and the health panel is green in `/admin/dashboard`; (f) restore `sooonax` autoconnect (`sudo nmcli con modify sooonax autoconnect yes`) if it was turned off for a test.
10. **Site wifi**: on site the SIM router's wifi is added with the fallback hotspot (phone) or `nmcli` over Tailscale; keep it higher priority than the hotspot profile.
11. **Not standardised yet** (add here once done): scheduled shutdown timer, read-only overlay root, switching the URL to `/k/<id>` after `/k/[id]` is deployed, self-hosted MediaPipe files.
